# 対局の記録の集め方

アプリで打ち始めた後に「最初から」や素材の切り替えをすると、結果(大成功 / 成功 / 失敗 / 途中でやめた)を選ぶ画面が出ます。
選ぶと、その対局の記録を Google スプレッドシートに送ってから、リセットします。

- **記録する中身:** 素材・設定、推奨手、打った手、入れた値(会心かどうかを含む)、温度・集中力の手直し、点灯の選択、取り消し、結果、最後の値。
- **名前は使いません:** 名前やログインは使いません。端末ごとのランダムな番号と、ブラウザ・OS の大まかな分類(例: iOS・Safari)を付けます。バージョンの番号などは送りません。
- **送れなかったとき:** 記録は端末に残り(最大50局)、次に開いたときや次の対局の終わりに送り直します。

## 送り先の作り方(最初に1回だけ)

1. Google スプレッドシートを新しく作ります。
2. メニューの [拡張機能] → [Apps Script] を開きます。
3. はじめからある中身を消して、`tools/log-collector.gs` の中身を貼り付け、保存します。
   - 上の関数の選択欄で `testPost` を選んで[実行]し、「記録」シートに結果が「試験」の行が1行入ることを確かめます(確かめたら行は消して構いません)。
   - エディタから `doPost` を直接実行すると、送られた中身が無いので止まります。これは正常です。
4. [デプロイ] → [新しいデプロイ] を押し、種類の歯車から「ウェブアプリ」を選びます。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
5. [デプロイ] を押します。初回は権限の確認が出るので、自分のアカウントで許可します。
6. 表示された「ウェブアプリ」の URL(`https://script.google.com/macros/s/…/exec`)をコピーします。
7. `gamelog.js` の `GLOG_ENDPOINT` の `'…'` の中に、その URL を入れます(今は設定済み)。

URL が空の版では、記録は送られずに端末に貯まります。URL が入った版を開くと、貯まっていた記録も送られます。
送り先を別のスプレッドシートに変えるときは、そちらで手順 1〜6 を行い、`GLOG_ENDPOINT` を新しい URL に書き換えます。
[新しいデプロイ] を作ると URL が変わります。前のデプロイをアーカイブすると、前の URL には送れなくなる(GET で 404 が返る)ので、
`GLOG_ENDPOINT` を新しい URL に書き換えて出します。届かなかった記録は端末に貯まっていて(最大50局)、書き換えた版を開いた時に送られます。

## 集まる形

スプレッドシートの「記録」シートに、1局が1行で入ります。

| 列 | 中身 |
|---|---|
| 結果 | 大成功 / 成功 / 失敗 / 途中でやめた |
| 素材・地金特性・職人Lv・ハンマー・できのよさ・許容誤差 | 打ち始めた時の設定 |
| 全マス到達・残り集中力・最後の温度・最後の値 | 結果を選んだ時の盤面 |
| 手数・取り消し | 「使った」を押した回数と、取り消した回数 |
| 手順(JSON) | 1手ずつの記録(推奨手 `rec`、打った手 `exec`、入れた値 `val`、手直し `edit`、点灯 `lit`、取り消し `undo`)。それぞれに、その時の温度・集中力・マスの値が付きます。入れた値 `val` には、叩いた技 `sk`・叩いた時の温度 `hitTemp`・点灯マスか `lit`・エンジンが見込んだ会心率 `cr`・会心でも会心でなくても出る値か `both` も付きます(どの打撃か分からない値は `amb`) |
| ブラウザ・OS | 大まかな分類(Safari / Chrome / Edge / Firefox / Samsung Internet / Opera / LINE / その他、iOS / iPadOS / Android / Windows / macOS / ChromeOS / Linux / その他) |

## 会心率の集計

エンジンの会心率の式のうち、確かめられていない上乗せを、集まった記録で確かめます。

- 威力会心率上昇の点灯マス: +400%(利用者の情報。公開された実測値は無い)
- ねらい打ち: +600%
- 集中力変化の会心ターン: +400%

**スプレッドシートで見る:** スクリプトを貼り替えた後にスプレッドシートを開き直すと、メニューに [鍛冶アドバイザー] が出ます。
[会心の集計を更新] を押すと、「会心の集計」シートに、**装備(ハンマー★できのよさ)**・地金特性・状況(点灯マス / 会心ターン / ふつう)・
技(ねらい系 / それ以外)ごとの、叩いた回数・会心の回数・会心率(実測とエンジンの見込み)が書かれます。

- **装備ごとに分ける理由:** ハンマーとできのよさで基礎の会心率が変わります(光★3 は 4.6%、光★2 は 3.8%)。混ぜると、ずれが
  ハンマーの会心率の値から来たのか、上乗せから来たのかを見分けられません。職人Lv30 未満の記録は「光★3 Lv25」のように別に分けます
  (職人スキルの会心アップは Lv30 で上限)。局の多い装備から順に並びます。
- **エンジンと合っているかの見方:** 「見込みとの差のz」が ±2 の中なら、実測の会心率はエンジンの見込みと誤差の範囲で一致しています
  (z = (会心の回数 − 見込みの会心率の合計) ÷ √(見込み×(1−見込み) の合計))。「判定」の列に「誤差の範囲」か「ずれ」が出ます。
  叩いた回数が30未満の行は「少ない」と出ます。実測の会心率には95%の範囲(下・上)も付きます。

**推定する:** 送り先の URL を GET で開くと、集計の数字だけが JSON で返ります(端末の番号や手順は返しません。10分ごとに作り直します)。

    curl -sL '<送り先の URL>' | node tools/crit-report.js
    curl -sL '<送り先の URL>' | node tools/crit-report.js - 光★3      (装備を1つに絞る)

装備ごとに、上乗せの推定値と95%の範囲、エンジンの値、範囲を狭めるのにあと何回の記録が要るかが出ます。
点灯マスは、同じ記録の「ふつうの状況・ねらい系でない技」の会心率との比でも求めます(ハンマーなどの基礎の会心率の仮定に頼らない)。

**数えない打撃:** 開始直後の1手(特性が乗らない)、必殺の効果中、みだれ打ち、まとめて実行して同じマスを2回以上叩いた打撃、
戻りで減った後の値、取り消した手。古い版のアプリの記録も、打った手と点灯マスから組み立て直して数えます。

**必要な量の目安:** 点灯マスの上乗せを ±100% まで絞るのに、点灯マスをねらい系でない技で叩いた記録が約300回(威力会心率上昇の商材で約80局)、
±50% までなら約1300回(約320局)。比で求める方は、その2倍ほどです。

## 注意

- 送り先の URL を知っていれば、誰でも書き込めます。いたずらで変な行が入ることがあるので、分析の前に明らかにおかしい行は除いてください。
- スクリプトを書き換えたときは、[デプロイ] → [デプロイを管理] → 鉛筆 → バージョン「新バージョン」で出し直してください(URL はそのまま使えます)。出し直さないと、GET の集計は動きません。
